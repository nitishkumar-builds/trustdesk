**Why the mock scores are perfect, and what the live numbers add.** The mock adapter (`server/src/ai/mockAdapter.ts`) is not a model: it is a set of hand-written rules keyed on the same eight seed tickets, so its triage labels and draft wording were written to satisfy the eval expectations, and its 1.000 across the board proves only that the pipeline, retrieval, guardrails and rule layers are wired correctly and deterministically. The live run replaces that one component with `google/gemini-2.5-flash` and keeps everything else, so the difference between the columns is the contribution of the model. Three things are visible: (1) the layers that are decided deterministically before or after the model did not move — citation coverage (category prior + required citations), unsafe-action blocking and the three adversarial cases (refusal templates chosen by the guardrail decision table, escalation forced by post-rules PR2–PR4) are identical; (2) the model-owned labels did move — the live model disagreed with the expected `priority` on five of eight tickets (it rates every security ticket and the damaged-earbuds ticket `urgent`/`high`) and with the `category` once (damaged earbuds → `warranty`), and it escalated two tickets the pack expects not to escalate, which is why `priority_accuracy` is 0.375 and `escalation_accuracy` 0.750; (3) one interaction between the model and the rules showed up: on eval_003 (final-sale software licence) the model asked to escalate, so the deterministic rule that adds `escalate_to_human` whenever the outcome is not `allow` (D-043) recommended an action on a case whose expectation allows none. eval_008 missed one answer requirement because the live draft did not ask for a transaction reference. No prompt, pattern, post-rule or threshold was changed to obtain these numbers.

**What was changed to complete the live run.** The first live attempt aborted at case 5 with `AI_PROVIDER_ERROR: OpenRouter returned non-JSON output`: the adapter treated any answer that did not parse as JSON as a provider failure, which ended the whole evaluation on one non-deterministic reply. `server/src/ai/openRouterAdapter.ts` now returns such an answer with `json` undefined (after also trying to extract a JSON object wrapped in prose), so the existing validation path applies — one corrective retry, then the deterministic fallback recorded as `model_output_invalid_fallback_applied` (D-033, D-075). This is a robustness change to the provider integration, not a scoring change; in the completed run above no call needed the retry or the fallback (no such note appears on any of its 16 traces).

Open items that would change these numbers further: paraphrased injections that the fixed pattern groups do not match, and removing the category prior from retrieval (citation coverage would then depend on full-text search alone).
