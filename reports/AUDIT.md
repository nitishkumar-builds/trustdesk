## 5. Attacks against the running API (actual responses)

Run on 2026-09-20 against http://localhost:4000 with the demo tokens, `AI_PROVIDER=mock`.

**Attack 1 — execute while `approval_required`.** `POST /api/tool-actions` (agent) for `create_replacement_order` on tkt_9001 → `201`, `status: "approval_required"`, `action_id: act_ej5cbwx14lpn8zvtz1u1u6ua`. `POST /api/tool-actions/act_ej5c…/execute` as agent and as manager → both `409 CONFLICT`: `"Action act_ej5c… is approval_required; it can only be executed from approved"`, `details: { current_status: "approval_required", executable_from: ["approved"], requires_human_approval: true }`. Status afterwards: `approval_required`, executor never ran. **Held.**

**Attack 2 — approve with the `support_agent` token.** `POST /api/tool-actions/act_ej5c…/approve` with `{decision: "approved"}` → `403 FORBIDDEN`, `"Role support_agent may not perform this action"`, `details: { required_roles: ["support_manager","admin"], route: "POST /api/tool-actions/:actionId/approve" }`. The odd-cased alias `/APPROVE` → `403` too (Express routes case-insensitively; the policy matcher is case-insensitive since `e8bd277`). Status afterwards: `approval_required`, 0 approval rows. **Held.**
