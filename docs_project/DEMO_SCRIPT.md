# TrustDesk — 6-minute explainer video script

Covers all 7 steps of the Recommended Demo Flow (TRUSTDESK_PROBLEM_STATEMENT.md) plus one adversarial case handled correctly. Everything below is done in the browser at `http://localhost:5173`; no curl.

**Before recording**

1. `docker compose up -d`, then `cd server && npm run db:seed -- --reset` (a clean seeded database, so the queue shows "not triaged" everywhere).
2. `npm run dev` at the repo root (API on :4000 with `AI_PROVIDER=mock`, web on :5173).
3. Open `http://localhost:5173`, click **Agent** in the header, set the browser to ~1440 px wide so the ticket page shows three columns.
4. Have `reports/EVALUATION_REPORT.md` open in an editor tab for the last 20 seconds.

The mock provider is deterministic: every click below produces exactly the text quoted here. If you record with `AI_PROVIDER=openrouter`, say so on camera and expect the draft wording to differ.

| Time | Screen / click | Say |
|---|---|---|
| **0:00–0:30** | Ticket queue (`/`) | "This is TrustDesk, an AI support-operations agent. It triages tickets, drafts grounded replies with policy citations, and only ever *recommends* tool actions — a human approves and executes them. Everything the AI does leaves a trace, and an eval runner scores it on eight provided cases, three of them adversarial." Point at the header: "Three demo tokens — Agent, Manager, Admin — drive the role-based gates you will see." |

Point at the blue **Policy context** box: "Return window and warranty are computed *as of the ticket's created_at* — never today's date — that's the line here, 2026-06-28. The customer message is rendered in the amber box labelled *untrusted*: it is data, never instructions." |
| **0:50–1:20** — **Step 2** | Click **Run Triage** | "Step two: AI triage." Read the badges: "Category *refund*, priority *medium*, sentiment *frustrated*, *no escalation*, with the reason 'Damaged or defective item reported'. The chips row shows which deterministic rules fired — none here. Those rules override the model on safety and security cases; we will see one fire later." |

Retrieved documents — refund, shipping, warranty policies — and note what is *not* there: KB-ADVERSARIAL-001 is quarantined and never used for grounding. Optionally switch the dropdown to the `triage` run: "Every triage, draft, tool request and eval case writes one of these." |

After the draft: "Guardrail outcome **refuse_and_escalate**, in red, with the refusal reason: prompt injection, instruction override, concealment, privilege escalation. The reply is a fixed refusal template, not model text, so an injection cannot talk its way into the wording. It cites **KB-SECURITY-001**. The mock provider is deterministic, so these numbers measure the pipeline's rules, retrieval and guardrails, not a live model; the report says so. That is TrustDesk." |

**If something goes off-script**

- A red banner at the bottom right is an API error with its code, message and request id; dismiss it and continue — nothing is swallowed.
- If `tkt_9001` already shows a triage or drafts (database not reset), the flow still works; the newest draft is shown and the trace panel follows the newest run.
- If the key `tkt_9001-create_replacement_order-1` already exists, the first request already answers *200 idempotent replay*: edit the key to `-2` to show a fresh 201, then repeat with `-2` for the replay.
